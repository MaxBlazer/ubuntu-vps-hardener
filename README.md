# Подготовка Ubuntu VPS

Один скрипт для свежей Ubuntu: пользователь с sudo, вход по SSH-ключу, случайный порт SSH, Docker, UFW, fail2ban, DNS, лимит логов и автообновления безопасности. Рассчитан на маленький VPS (1 CPU, 1 GB RAM, 10 GB диск).

Запускать от root по первому SSH-входу с паролем от провайдера. После успешного прогона root по SSH закрыт, пароль по SSH не принимается. Пароль root в системе остаётся: веб-консоль провайдера (VNC) по-прежнему им пользуется. Это отдельный вход, не SSH.

## Запуск

Скопируйте `bootstrap.sh` на сервер и выполните:

```bash
bash bootstrap.sh \
  --user maxblazer \
  --ssh-key 'ssh-ed25519 AAAA... comment'
```

Либо, когда файл лежит в репозитории:

```bash
curl -fsSL https://raw.githubusercontent.com/<user>/<repo>/main/bootstrap.sh | bash -s -- \
  --user maxblazer \
  --ssh-key 'ssh-ed25519 AAAA... comment'
```

Пока скрипт не закончился и вы не проверили вторую сессию, текущее окно root не закрывайте.

Проверка входа:

```bash
ssh -p PORT maxblazer@SERVER_IP
```

Порт печатается в конце и записан в `/root/.vps_preparer_ssh_port`. Если сессия уже потеряна, откройте консоль провайдера и выполните `cat /root/.vps_preparer_ssh_port`.

## Параметры

| Параметр | Обязательный | Смысл |
|---|---|---|
| `--user NAME` | да | Имя пользователя (sudo без пароля, группа docker) |
| `--ssh-key '...'` | да, можно несколько раз | Публичный ключ: ed25519, ecdsa или security key (passkey). RSA и DSA отклоняются |
| `--github-user LOGIN` | нет | Добавить ключи с `https://github.com/LOGIN.keys`. Строки RSA/DSA пропускаются |
| `--ssh-port PORT` | нет | Свой порт (1024–65535). Без этого флага порт выбирается из 49152–65535 и при повторном запуске берётся из файла |

Хотя бы один подходящий ключ должен встать до смены настроек SSH. Если ключ не записался, скрипт останавливается и sshd не трогает.

## Что меняется

- Пакеты обновляются, ставится базовый набор (zsh, git, ufw, fail2ban, unattended-upgrades).
- Swap 512M, если свопа ещё нет. На 1 GB RAM это нужно, чтобы `apt` и Docker не упирались в память.
- Oh My Zsh с плагинами `git`, `docker`, `docker-compose`.
- Docker Engine и Compose. Сам движок занимает сотни мегабайт; место съедают образы и контейнеры. Скрипт образы не скачивает.
- DNS: Quad9, Cloudflare, Google.
- Журнал systemd ограничен 100M.
- Обновления безопасности ставятся сами, автоматической перезагрузки нет.
- UFW: снаружи открыт только новый SSH-порт. 22, 80 и 443 не открываются.
- fail2ban банит IP на сутки после 5 неудачных попыток SSH за час. Своего IP в исключениях нет (статического адреса нет).
- sshd: порт из файла, `PermitRootLogin no`, только ключи. Настройки провайдера в `sshd_config.d` переписываются так же, иначе они могут оставить вход по паролю.

Повторный запуск безопасен и не меняет уже выбранный порт. Новый порт задаётся через `--ssh-port`.

Группа `docker` начинает действовать со следующего входа.

Когда понадобятся сайты:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

## Проверка

```bash
ssh -p PORT USER@SERVER_IP
sudo -n true
ufw status
fail2ban-client status sshd
docker version
```
